
限速算法

### 令牌桶 是什么意思？

⏺ 令牌桶（Token Bucket）

  一种经典的限流算法，用水桶的比喻来理解：

      [以固定速率放入令牌]
             │
             ▼
      ┌─────────────┐
      │  ○ ○ ○ ○ ○  │  ← 桶（有容量上限）
      │  ○ ○ ○ ○    │
      └──────┬──────┘
             │
             ▼
        取走一个令牌 → 请求放行
        桶空了       → 请求拒绝（429）

  核心规则

  1. 系统以固定速率往桶里放令牌（比如每秒 10 个）
  2. 桶有容量上限（比如最多 20 个）——满了就不再放入
  3. 每个请求来了，从桶里取一个令牌——取到就放行，取不到就拒绝

  对应之前的配置

  ┌────────────────────┬──────────────────────────────────────────┐
  │        参数        │                   含义                   │
  ├────────────────────┼──────────────────────────────────────────┤
  │ replenishRate = 10 │ 每秒往桶里放 10 个令牌 → 稳定速率 10 QPS │
  ├────────────────────┼──────────────────────────────────────────┤
  │ burstCapacity = 20 │ 桶最多装 20 个 → 允许短时突发 20 个请求  │
  └────────────────────┴──────────────────────────────────────────┘

  为什么允许突发？

  假设系统空闲了 2 秒，桶里攒了 20 个令牌。这时突然来 20 个请求，全部能拿到令牌放行。这就是"
  突发"——短时间内允许超过稳定速率，但不会持续超标，因为令牌补充速率是固定的。

  和其他限流算法对比

  ┌──────────────────────┬──────────────────────────────┐
  │         算法         │             特点             │
  ├──────────────────────┼──────────────────────────────┤
  │ 令牌桶               │ 允许突发，平滑限流，最常用   │
  ├──────────────────────┼──────────────────────────────┤
  │ 漏桶（Leaky Bucket） │ 严格匀速，不允许突发         │
  ├──────────────────────┼──────────────────────────────┤
  │ 固定窗口计数器       │ 简单，但有边界突刺问题       │
  ├──────────────────────┼──────────────────────────────┤
  │ 滑动窗口计数器       │ 比固定窗口更平滑，实现稍复杂 │
  └──────────────────────┴──────────────────────────────┘

  简单总结：令牌桶 = 匀速发"通行证"，攒够了可以突发用，用完就排队等。
