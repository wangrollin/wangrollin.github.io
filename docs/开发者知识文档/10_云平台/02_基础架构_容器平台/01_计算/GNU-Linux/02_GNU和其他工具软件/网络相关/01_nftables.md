
## Q&A

### iptables / nftables 在 Rocky Linux 中的作用

  是什么

  两者都是 Linux 内核态防火墙框架的用户态工具：

  - iptables — 传统工具，通过 Netfilter 框架操作内核中的包过滤规则
  - nftables — iptables 的继任者（Rocky 8+ 默认），统一了
  iptables/ip6tables/arptables/ebtables

  解决什么问题

  ┌─────────────────────────────────┬───────────────────────────────────────────────────┐
  │              功能               │                       说明                        │
  ├─────────────────────────────────┼───────────────────────────────────────────────────┤
  │ 包过滤（Packet Filtering）      │ 按规则允许/拒绝/丢弃网络包                        │
  ├─────────────────────────────────┼───────────────────────────────────────────────────┤
  │ NAT（网络地址转换）             │ SNAT、DNAT、端口转发、IP 伪装                     │
  ├─────────────────────────────────┼───────────────────────────────────────────────────┤
  │ 连接跟踪（Connection Tracking） │ 实现有状态防火墙，区分 NEW/ESTABLISHED/RELATED    │
  ├─────────────────────────────────┼───────────────────────────────────────────────────┤
  │ 流量整形/标记                   │ mangle 表修改包头（TTL、TOS、MARK），配合策略路由 │
  ├─────────────────────────────────┼───────────────────────────────────────────────────┤
  │ 日志与审计                      │ 记录匹配特定规则的流量                            │
  └─────────────────────────────────┴───────────────────────────────────────────────────┘

  Rocky Linux 中的现状

  - Rocky 8/9 底层都是 nftables
  - firewalld（默认前端）在后端已切换为 nftables
  - iptables 命令仍可用，但实际是 iptables-nft（兼容层，规则最终转成 nftables）

### 可以理解 nftables 是rockylinux 的网络协议栈实现吗？

⏺ 不是。 两者是完全不同的东西。

  区分

  ┌───────────┬────────────────────────────────────────────┬─────────────────────────────┐
  │           │                 网络协议栈                 │          nftables           │
  ├───────────┼────────────────────────────────────────────┼─────────────────────────────┤
  │ 是什么    │ Linux 内核中实现 TCP/IP 协议的核心子系统   │ 挂载在协议栈上的包过滤/处理 │
  │           │                                            │ 框架                        │
  ├───────────┼────────────────────────────────────────────┼─────────────────────────────┤
  │ 职责      │ 封装/解封装、路由、拥塞控制、连接管理等——  │ 在包经过协议栈的特定点上做  │
  │           │ 让网络通信能工作                           │ 检查和干预                  │
  ├───────────┼────────────────────────────────────────────┼─────────────────────────────┤
  │ 类比      │ 高速公路本身                               │ 高速公路上的收费站/检查站   │
  ├───────────┼────────────────────────────────────────────┼─────────────────────────────┤
  │ 没有它会  │ 网络完全不通                               │ 网络正常工作，只是没有防火  │
  │ 怎样      │                                            │ 墙规则                      │
  └───────────┴────────────────────────────────────────────┴─────────────────────────────┘

  关系

  网络包进入
      │
      ▼
  ┌──────────────────────────────────────┐
  │         Linux 网络协议栈              │
  │  (IP层、TCP/UDP层、路由子系统等)       │
  │                                      │
  │   在关键路径上预留了 5 个 hook 点：    │
  │   PREROUTING / INPUT / FORWARD /     │
  │   OUTPUT / POSTROUTING               │
  │                                      │
  │   ┌──────────────────┐               │
  │   │  Netfilter 框架   │ ◄── hook 机制 │
  │   │  ┌──────────┐    │               │
  │   │  │ nftables │    │ ◄── 具体实现   │
  │   │  └──────────┘    │               │
  │   └──────────────────┘               │
  └──────────────────────────────────────┘

  简单说：协议栈是主体，Netfilter 是协议栈预留的钩子机制，nftables
  是利用这些钩子实现防火墙功能的工具。 三者是包含关系，不是同一个东西。

## firewalld 也是基于 nftables 实现的吗？

⏺ 是的。 在 Rocky 8/9 中，firewalld 的后端已经从 iptables 切换为 nftables。

  层级关系

  ┌─────────────────────────────┐
  │  用户 (管理员)               │
  │  firewall-cmd / cockpit UI  │  ◄── 用户界面
  └──────────┬──────────────────┘
             ▼
  ┌─────────────────────────────┐
  │  firewalld (守护进程)        │  ◄── 高层管理工具（zone/service/rich rule）
  └──────────┬──────────────────┘
             ▼
  ┌─────────────────────────────┐
  │  nftables                   │  ◄── 底层规则引擎
  └──────────┬──────────────────┘
             ▼
  ┌─────────────────────────────┐
  │  Netfilter (内核)            │  ◄── 内核中实际执行包过滤
  └─────────────────────────────┘

  firewalld 解决了什么问题

  直接写 nftables 规则有门槛，firewalld 在其之上提供了更友好的抽象：

  ┌──────────────────────────────┬────────────────────────────────┐
  │        firewalld 概念        │         对应的底层操作         │
  ├──────────────────────────────┼────────────────────────────────┤
  │ zone（public/trusted/drop…） │ 自动生成一组 nftables 链和规则 │
  ├──────────────────────────────┼────────────────────────────────┤
  │ service（http/ssh/dns…）     │ 按预定义端口生成 accept 规则   │
  ├──────────────────────────────┼────────────────────────────────┤
  │ rich rule                    │ 转化为具体的 nftables 规则     │
  ├──────────────────────────────┼────────────────────────────────┤
  │ runtime / permanent          │ 区分内存中的规则和持久化配置   │
  └──────────────────────────────┴────────────────────────────────┘

  一个例子
```bash
  # 你执行
  firewall-cmd --add-service=http --permanent

  # firewalld 实际做的事：往 nftables 中插入类似这样的规则
  nft add rule inet firewalld filter_IN_public_allow tcp dport 80 accept
```

  所以 firewalld 是管理工具，nftables 是执行引擎，两者不是替代关系，而是上下层关系。

## 它们各自操作内核的不同子系统

  ┌──────────────────────────────────────────┐
  │              Linux 内核网络协议栈           │
  │                                          │
  │  ┌──────────────┐    ┌────────────────┐  │
  │  │ 网卡/地址/路由 │    │   Netfilter    │  │
  │  │   子系统      │    │   (包过滤)     │  │
  │  └──────┬───────┘    └───────┬────────┘  │
  │         │                    │           │
  └─────────┼────────────────────┼───────────┘
            │                    │
            ip                nftables

  简单总结：ip 管的是"网络怎么连"，nftables 管的是"包让不让过"。
  它们是并列关系，不是上下游关系。

## ip 命令和 nftables 使用的是内核中完全不同的接口

  对比

  ┌──────────┬────────────────────────────────┬────────────────────────────┐
  │          │            ip 命令             │          nftables          │
  ├──────────┼────────────────────────────────┼────────────────────────────┤
  │ 内核接口 │ Netlink 套接字                 │ Netfilter hooks            │
  ├──────────┼────────────────────────────────┼────────────────────────────┤
  │ 做什么   │ 配置网卡、地址、路由等网络状态 │ 在数据包路径上插入过滤规则 │
  ├──────────┼────────────────────────────────┼────────────────────────────┤
  │ 性质     │ 管理/配置通道                  │ 数据面拦截点               │
  └──────────┴────────────────────────────────┴────────────────────────────┘

  两种完全不同的机制

  ┌─────────────────────────────────────────────────┐
  │                Linux 内核网络协议栈                │
  │                                                  │
  │  ┌─────────────────┐     ┌───────────────────┐  │
  │  │  网卡/地址/路由   │     │    Netfilter      │  │
  │  │  配置数据结构     │     │    hook 点        │  │
  │  └────────┬────────┘     └────────┬──────────┘  │
  │           │                       │              │
  │     Netlink 接口             Netfilter 接口      │
  └───────────┼───────────────────────┼──────────────┘
              │                       │
           ip 命令               nft 命令
         "请把 eth0 的            "请在 PREROUTING
          IP 设为 x"              挂一条 drop 规则"

  - Netlink：用户态与内核之间的通信协议（一种特殊的
  socket），用来读写内核中的网络配置状态。不涉及数据包路径。
  - Netfilter hooks：内核在数据包经过协议栈时预留的拦截点，用来对每个包做检查和处理。

  类比

  ┌───────────────┬──────────────────────────────┬────────────────────────────────┐
  │               │           ip 命令            │            nftables            │
  ├───────────────┼──────────────────────────────┼────────────────────────────────┤
  │ 类比          │ 去交管局登记车牌、设定路线   │ 在路上设卡检查每辆车           │
  ├───────────────┼──────────────────────────────┼────────────────────────────────┤
  │ 作用时机      │ 管理员执行命令时，一次性配置 │ 每个数据包经过时，实时逐包执行 │
  ├───────────────┼──────────────────────────────┼────────────────────────────────┤
  │ 数据面/控制面 │ 控制面                       │ 数据面                         │
  └───────────────┴──────────────────────────────┴────────────────────────────────┘

  总结：ip 通过 Netlink 做网络配置（控制面），nftables 通过 Netfilter hooks
  做包过滤（数据面）。两者操作内核的方式完全不同。
