
⏺ SELinux (Security-Enhanced Linux)

  SELinux 是由 NSA 开发、集成在 Linux 内核中的**强制访问控制（MAC）**安全模块。

  解决的核心问题

  传统 Linux 使用自主访问控制（DAC）——权限由文件所有者决定（rwx）。这有几个根本缺陷：

  1. root 权限过大 — root 可以做任何事，一旦某个以 root 运行的服务被攻破，攻击者就拥有整个系统的控制权
  2. 权限粒度粗 — DAC 只能控制"谁能读/写/执行文件"，无法限制进程能访问哪些网络端口、能与哪些其他进程通信等
  3. 用户可自行放宽权限 — 文件所有者可以随意 chmod 777，破坏安全策略

  SELinux 的做法

  给系统中的每个对象（文件、进程、端口、socket 等）打上安全标签（context），然后通过策略规则定义"哪个标签的进程可以对哪个标签的资源做什么操作"。

  # 示例：Apache 进程的上下文
  system_u:system_r:httpd_t:s0

  # 网页文件的上下文
  system_u:object_r:httpd_sys_content_t:s0

  # 策略：httpd_t 可以读取 httpd_sys_content_t，但不能读 /etc/shadow

  实际效果

  - 即使 Apache 被攻破拿到 root，攻击者也只能访问策略允许的资源，无法读取 /etc/shadow、无法监听非 HTTP 端口
  - 每个服务被限制在最小权限范围内（最小权限原则）
  - 用户/进程无法自行绕过策略（由内核强制执行）

  三种模式

  ┌────────────┬──────────────────────────────────┐
  │    模式    │               行为               │
  ├────────────┼──────────────────────────────────┤
  │ Enforcing  │ 强制执行策略，拒绝违规访问       │
  ├────────────┼──────────────────────────────────┤
  │ Permissive │ 不拒绝，只记录违规日志（调试用） │
  ├────────────┼──────────────────────────────────┤
  │ Disabled   │ 完全关闭                         │
  └────────────┴──────────────────────────────────┘

  getenforce          # 查看当前模式
  setenforce 0        # 临时切换到 Permissive

  一句话总结

  SELinux 在传统 rwx 权限之上加了一层内核级强制访问控制，让每个进程只能做策略明确允许的事，即使被攻破或拥有 root 权限也无法越界。
