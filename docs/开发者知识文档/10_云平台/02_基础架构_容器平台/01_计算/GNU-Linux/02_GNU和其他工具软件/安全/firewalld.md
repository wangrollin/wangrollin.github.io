
### SELinux 和 firewalld 是什么关系？

⏺ 没有直接关系，是两个独立的安全层，各管各的：

  ┌──────────┬────────────────────────────────┬─────────────────────────────────────────┐
  │          │           firewalld            │                 SELinux                 │
  ├──────────┼────────────────────────────────┼─────────────────────────────────────────┤
  │ 管什么   │ 网络流量 — 哪些端口/IP允许通信 │ 进程权限 — 谁能访问哪些文件、端口、资源 │
  ├──────────┼────────────────────────────────┼─────────────────────────────────────────┤
  │ 工作层   │ 网络层（iptables/nftables）    │ 内核层（强制访问控制 MAC）              │
  ├──────────┼────────────────────────────────┼─────────────────────────────────────────┤
  │ 典型场景 │ "外部能不能连 5432 端口"       │ "httpd 进程能不能绑定 8080 端口"        │
  └──────────┴────────────────────────────────┴─────────────────────────────────────────┘

  一个请求要同时过两关。 比如外部访问 PostgreSQL：

  1. firewalld — 5432 端口放行了吗？
  2. SELinux — PG 进程有权限监听这个端口吗？

  两者任一拦截都会失败，但报错表现不同：
  - firewalld 拦截 → 连接超时/拒绝
  - SELinux 拦截 → 服务启动失败或 Permission denied，日志在 /var/log/audit/audit.log
