
## 使用

在本地生成 HTTPS 证书：

```bash
# 安装
brew install mkcert

# 安装本地 CA 到系统信任存储
mkcert -install

# 生成证书
mkcert localhost 127.0.0.1 ::1

# 生成的证书会被系统自动信任，浏览器不会报警告。
```

## Q&A

### certbot和mkcert有什么区别，使用场景的区别和联系是什么？

⏺ ┌──────────────┬────────────────────────┬─────────────────────────────┐
  │              │         mkcert         │           certbot           │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 签发者       │ 本地自建 CA            │ Let's Encrypt（公共 CA）    │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 信任范围     │ 仅安装了该 CA 的本机   │ 所有浏览器/设备，全球信任   │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 是否需要域名 │ 不需要，localhost 即可 │ 需要，且 DNS 指向你的服务器 │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 是否需要公网 │ 不需要                 │ 需要（或能操作 DNS）        │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 证书有效期   │ 自定义（默认很长）     │ 90 天，自动续期             │
  ├──────────────┼────────────────────────┼─────────────────────────────┤
  │ 使用场景     │ 本地开发/测试          │ 生产环境                    │
  └──────────────┴────────────────────────┴─────────────────────────────┘

  核心区别

  信任链不同：
  - mkcert 创建的 CA 只存在于你本机的信任存储里，别人的浏览器访问会报"不安全"
  - certbot 从 Let's Encrypt 获取证书，全球所有浏览器预装了 Let's Encrypt 的根证书，天然信任

  典型工作流

  开发阶段: mkcert localhost → 本地 nginx/webpack 用 HTTPS 调试
      ↓
  上线部署: certbot --nginx -d prod.example.com → 生产 nginx 用真证书

  联系

  两者解决的是同一个问题（获取 TLS 证书），只是作用域不同：

  - mkcert = 给自己用，零门槛
  - certbot = 给公众用，需要证明你拥有域名

  简单记：本地开发用 mkcert，生产上线用 certbot。
